# Наши правки к Combat Extended

Здесь лежит всё, что мы меняем **внутри** CE, а не у себя. Отдельно — потому что клон CE живёт за
пределами этого репозитория (сейчас `D:\Mods\CombatExtended`; переезд в `D:\Mods\Updated\` ждёт
момента, когда папку не держит редактор), и при его обновлении правки нужно уметь показать,
проверить и наложить заново.

В игру клон подключён junction'ом с именем **`CombatExtended`** — именно так, без суффикса:
`SK.CEPatchPatch` узнаёт файлы самой CE по подстроке `/CombatExtended/` в пути, и с
`CombatExtended-git` принимал их за чужой мод.

## Почему правки вообще внутри CE

Hardcore SK не работает с нетронутой CE. Он поставляется со своей копией, где 222 файла дефов
переименованы в `.xml.bak`, а 28 отредактированы, и его сгенерированные патчи написаны под такую
форму. Проверено по трём копиям сразу: узла `statBases/MarketValue`, который заменяют патчи пака,
нет ни в апстримной 1.6, ни в 1.7 — он есть **только** в паковой копии. То есть такие правки —
это правки HSK внутри CE, и повторять их надо там же.

Признак, по которому решается, где чинить:

| Причина | Где править |
|---|---|
| узел или деф есть только в паковой копии CE | в CE |
| пак называет то, чего нет ни в одной CE | у нас, папка `HSK/` |
| дефы пака нуждаются в типах CE, которой нет | у нас, папка `NoCE/` |

Core SK не правим никогда.

## Что здесь

| Файл | Что это |
|---|---|
| `0001-*.patch` | наши правки к CE одним коммитом, в формате `git format-patch` |
| `PortHSKEdits.py` | переносит правки HSK на любую версию CE и отключает файлы по списку |
| `disabled-files.txt` | 222 файла патронов, которые пак отключает `.xml.bak` |
| `deleted-files.txt` | 48 патчей CE, которые пак из своей копии удаляет совсем |
| `added-files.txt` | 5 дефов и патчей, которые пак в CE добавляет от себя |
| `FindRefHolders.py` | по логу прогона помогает разобрать повисшие ссылки |

## Как наложить на свежий клон CE

```
git clone https://github.com/CombatExtended-Continued/CombatExtended
cd CombatExtended && git checkout 1.7-Test && git checkout -b hsk-compat
git am ../HSKVanilla/Tools/CEPatches/0001-*.patch
```

Если патч не лёг (CE успела изменить те же файлы), он не нужен — правки воспроизводятся заново:

```
python Tools/CEPatches/PortHSKEdits.py \
  --upstream "D:\Mods\.tmp\CE-upstream\v1600\CombatExtended" \
  --pack     "D:\RimWorld_HSK\Mods\CombatExtended" \
  --target   "D:\Mods\CombatExtended"
```

`--upstream` — апстримная CE **того же номера, что у пака** (`modVersion` в его `About.xml`;
сейчас `16.7.0.0`, то есть релиз `v1.6.7.0.0`). Без этого дифф смешает правки HSK с развитием самой
CE. `--dry-run` покажет список файлов, ничего не меняя.

После переноса — обновить патч одной командой из клона:

```
git format-patch -o <этот каталог> --zero-commit origin/1.7-Test
```

## Что именно изменено

**24 файла перенесены** — по диффу «апстрим 1.6 → паковая копия»: патроны (`303British`,
`556x45mmNATO`, `762x39mmSoviet`, `762x51mmNATO`, `45ACP`, `9x19mmPara`, `50BMG`, `Arrows`,
`30x29mmGrenade`, `40x46mmGrenade`, `RPG7`, `SPG9`, `81mmMortar`, `5x50mmCaseless`, `6x24mmCharged`,
`30x64mmFuelCell`, `Flamethrower`, `Flare`, `Flamethrower_Burst`) и патчи CE к ванилле (`Drugs`,
`Duties_Misc`, `Damages_LocalInjury`, `Weapons_Guns`, `QuadrupedAnimalWithPawsAndTail`).

**Сдвиг путей DLC.** В 1.7 CE переложила патчи DLC на уровень глубже: `Biotech/Patches/X` стало
`Biotech/Patches/Biotech/X`. Сравнение по прямым путям эти папки пропускало целиком — отсюда были
«не применилось» у брони Biotech и способностей Royalty, и отсюда же оставались четыре последние
ошибки: в `RangedIndustrial_Biotech.xml`, который пак удаляет, а он ставит `smeltable=false`
гранате `Weapon_GrenadeTox` и называет `AmmoSet_LauncherGrenade`. Скрипт теперь сдвигает путь сам
(`resolve`), так что 27 из 28 файлов переносятся; 28-й (`Buildings_Mechanoid` у Royalty) в 1.7 уже
содержит то же самое.

**222 файла отключены** — весь список пака, и это принципиально. Сначала я отключил только те 15,
чьи дефы встречались в логе: 61 ошибка ушла, но пришли 63 новые. Те же файлы объявляли шесть общих
наборов патронов (`AmmoSet_Rifle`, `AmmoSet_RifleIntermediate`, `AmmoSet_AntiMateriel`,
`AmmoSet_ArtilleryShell`, `AmmoSet_HeavyCannon`, `AmmoSet_LightCannon`), на которые десятки других
наборов CE смотрят через `similarTo`, а эти — лежат в файлах, которые пак тоже отключает.
Урезание непротиворечиво только целиком. В `Defs/Ammo` осталось 45 активных файлов против 41 у пака.

**48 патчей CE отключены** — их пак из своей копии удаляет: это патчи CE к ванилле, которые он
заменяет своими. Среди них `Patches/Core/ThingDefs_Misc/Weapons_Grenades.xml`, где
`smeltable=false` конфликтовал с `smeltProducts` пака (9 `Config error`), и
`Biotech/Patches/Biotech/ThingDefs_Misc/Weapons/RangedIndustrial_Biotech.xml` (ещё 4). Мы не
удаляем, а переименовываем: результат тот же, а в логе и в `git status` видно, что сделано.

**5 файлов скопированы** из паковой копии — это дефы и патчи, которых в апстримной CE нет совсем.
Без этого шага отключение по `deleted-files` выносит контент: пак удаляет апстримный
`Defs/Ammo/HighCaliber/14.5x114mmSoviet.xml`, но взамен кладёт свой `14.5x114mm.xml`. Я сначала
отключил первый и не положил второй — 35 патчей пака к этим патронам промахнулись, и ошибок стало
62 вместо 49.

**106 текстур скопированы** из паковой копии: часть арта пак добавляет в CE сам (снаряды 120 мм и
флак, приборы ночного видения и прочее), и его же дефы на этот арт ссылаются. В апстримной CE
этих файлов нет ни в 1.6, ни в 1.7.

**`ModPatches` отключена** — все 769 записей убраны из `LoadFolders.xml`. Пак поставляется с CE без
этой папки вовсе (3819 файлов), сохраняя при этом сами записи — они указывают в пустоту. У нас папка
есть, и при полном составе модов она грузится для всего установленного, принося ссылки на
отключённый паком контент: патч совместимости CE с Androids выдавал в сценарии
`Ammo_762x54mmR_FMJ`, который лежит в `.bak`-списке пака. Файлы оставлены на месте — довольно того,
что игра их не подключает, и диff выходит в пять строк вместо 3819 удалений.

Это, кстати, отменяет мой более ранний вывод «ModPatches трогать не нужно»: он был сделан на
минимальном списке модов, где ни один из них в условиях `IfModActive` не совпадал.

**`global.json`** прибит к установленному локально SDK (10.0.401): ветка целится в `net10.0`, а в
файле стояло 9.0.112, что не принимает ни 8, ни 10.

## Результат по прогонам

| | ошибок в логе |
|---|---|
| пак + нетронутая CE 1.7 | 138 |
| перенос правок + 15 файлов отключено | 113 |
| весь список 222 | 49 |
| плюс 32 патча и текстуры, но без 5 добавленных файлов | 62 |
| плюс эти 5 файлов | 15 |
| плюс папки DLC (16 отключений и 3 переноса) | 6 |
| плюс снайпер, `similarTo` и мех-турель | 3 (две из них — от правки `similarTo`) |
| откат `similarTo` и снятие дубля у `Gun_Minigun` | 1 |
| снят `similarTo` у нового набора 1.7 | 0 |

С полным составом модов (172 мода, не минимальный список) остаётся 2 ошибки: `CE_Apparel_MeleeShield`
— пак сам удаляет этот деф и сам же на него ссылается из `whiteApparelList` расовых модов; и
`Ammo_762x54mmR_FMJ` из патча совместимости `ModPatches`, который теперь отключён.

Отдельно — правки, где виновата не HSK, а новшества самой 1.7:

- `weaponMoney` у снайперов-наёмников. CE 1.6 этот деф не трогает вовсе; 1.7 добавляет `415~600`
  только абстрактной базе — это ниже 950, сколько стоит самая дешёвая снайперская винтовка пака, и
  вдобавок оставляет `PatchOperationReplace` пака по дочерним дефам без цели. Заменено операцией,
  которая кладёт узел и базе, и детям, значением выше порога; пак затем ставит своё.
- две записи осколков в новом `Ammo_ChargedRockets.xml`, указывающие на снаряды из отключённого
  файла.

Ещё одна правка — снято удаление `equippedStatOffsets` у `Gun_Minigun`: ровно это же делает своим
патчем пак, он грузится после CE и промахивался по уже отсутствующему узлу. Итог тот же, узел
убирает пак.

**Про `similarTo` — показательный случай.** Таких узлов, указывающих на отключённый
`AmmoSet_LauncherGrenade`, было три, и они требуют разного обращения:

- два у `AmmoSet_30x29mmGrenade` и `AmmoSet_40x46mmGrenade` — **трогать нельзя**: пак удаляет их
  своими патчами (`Patches/Mods_CombatExtended/Ammo/Grenade/*.xml`). Я их убрал, и получил две
  новые ошибки: операциям пака стало нечего удалять, а в его игре повисшей ссылки и не было;
- третий у `AmmoSet_40x46mmOnlyEMP` — **убран**: набор новый в 1.7, пак его не видел и не патчит,
  так что промахнуться нечему.

Правило: прежде чем убирать узел, на который кто-то ссылается, проверить, не удаляет ли его сам
пак. И наоборот — у того, чего в версии пака не было, проверять некому, и тогда решать по месту.

## Что осталось и почему это не наше

| Ошибка | Чья |
|---|---|
| `[Minerals] PatchOperationFindMod(Core SK)` | мода Minerals: ищет мод по имени «Core SK». В последнем прогоне не появилась |

Про `6x22mmCharged` я сначала написал, что это баг пака, и ошибся. Ссылки ставит сама CE, в своём
новом файле 1.7 `Patches/Core/ThingDefs_Misc/Weapons_Mech_Turrets.xml`, которого пак не видел и
потому не правил. Патроны при этом в его списке отключённых. Переставил мех-мини-турель на
`6x24mmCharged` — ближайший живой заряженный калибр, который пак держит активным и сам правит.
